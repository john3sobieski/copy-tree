## Суть проекта

Утилита для Windows 10 на Rust. Пункт "CopyTree" в контекстном меню Проводника (ПКМ):

- по **папке**: в буфер обмена копируется дерево папки (папки и файлы) в формате `tree` с символами `├──`, `└──`, `│`. Нужно, чтобы скинуть ИИ структуру проекта.
- по **файлу**: в буфер копируется только абсолютный путь к файлу одной строкой, от корня диска (например `C:\proj\src\main.rs`), без кавычек и без дерева.

Фонового процесса нет. Windows сама запускает exe с путём в аргументе, программа делает работу и закрывается.

## Стек и ключевые решения

- Язык: Rust, один exe без зависимостей.
- Крейты: `ignore` (обход папок, поддержка `.gitignore`), `arboard` (буфер обмена), `winreg` (реестр), `serde` + `toml` (конфиг).
- Запись в реестр только в `HKCU\Software\Classes`, права администратора не нужны.
- `#![windows_subsystem = "windows"]`, чтобы не мигало окно консоли.
- Конфиг `copytree.toml` лежит рядом с exe. Дефолтный конфиг вшит в бинарник (`include_str!`) и записывается рядом с exe (в закомментированном виде), если файла нет. Пользователь раскомментирует нужную настройку, пересборка не нужна.
- Лицензия: PolyForm Noncommercial License 1.0.0, автор в лицензии: GitHub-ник `john3sobieski`.

## Решения и заметки

- Конфиг (этап 2): дефолт лежит в `copytree.default.toml` в корне проекта и вшивается в exe через `include_str!`. При первом запуске записывается как `copytree.toml` рядом с exe (если папка недоступна на запись, работают дефолты). Удалить файл = вернуть дефолты. Файл создаётся с закомментированными настройками: незакомментированная строка = осознанное переопределение, остальное берётся из дефолта текущей версии exe (иначе старые лимиты замораживались бы в файле после обновления). Старые конфиги, созданные до этого изменения, содержат все значения как есть: их нужно удалить один раз.
- Отсутствующий ключ в `copytree.toml` берётся из дефолта. Если `ignore` задан, он **полностью заменяет** дефолтный список, а не дополняет его. Опечатка в имени ключа считается ошибкой (`deny_unknown_fields`). UTF-8 BOM в начале файла срезается.
- Игнор-список из конфига работает на уровне имён и масок в стиле `.gitignore` и применяется ко всему, что внутри выбранной папки, но не к самой выбранной папке (ПКМ по `node_modules` покажет её содержимое).
- `.gitignore` читается только внутри выбранной папки и ниже, родительские папки не учитываются (так клик по папке, которую игнорирует родитель, не даёт пустой результат). Глобальный gitignore пользователя и `.ignore` не читаются.
- Лимит `max_entries`: обход в глубину, поэтому при обрезке пропадают поздние в алфавите папки верхнего уровня. Папки на предельной глубине не помечаются, даже если внутри что-то есть.
- Проект публичный: комментарии в коде на английском, 1-2 строки, README на английском. Звуков нет.
- Этап 1: обход изначально был на `ignore::WalkBuilder` (`standard_filters(false)`), теперь свой (см. заметку про пропущенные папки ниже). Скрытые файлы показываются. Симлинки не разворачиваются, показываются как файлы, поэтому циклов нет.
- Сортировка (после перехода на свой обход) использует уже известный тип записи и заранее посчитанный ключ в нижнем регистре, лишних обращений к ФС нет.
- В песочнице Claude старый cargo 1.75: там транзитивные зависимости (`ignore`, `indexmap`, `toml` и др.) пришлось закреплять на старых версиях в локальном `Cargo.lock`. На обычном современном Rust (`rustup`) этого не нужно, `Cargo.lock` генерируется сам, `Cargo.toml` не менялся.
- Проверка папки без доступа в песочнице невозможна (root обходит права), её надо проверить на Windows.
- Форматы буфера: файл = абсолютный путь одной строкой от корня диска; папка = `tree`-дерево с корнем в выбранной папке. Поиск корня проекта (`.git`, `Cargo.toml`) не нужен.
- CI (`build.yml`): `windows-latest`, `cargo build --release`, артефакт `copytree-windows-x64` (только exe, конфиг вшит). Автоматического GitHub Release нет (решение пользователя: релизы публикует вручную), в `build.yml` только сборка и артефакт. Триггер по тегу `v*` остался, он запускает сборку. `.cargo/config.toml` включает статический CRT (`+crt-static`), чтобы exe работал без VC++ Redistributable. `Cargo.lock` не был в архиве: после первой сборки его стоит закоммитить (это бинарник).
- Этап 3: `arboard` с `default-features = false` (картинки не нужны). Абсолютный путь файла через `std::path::absolute` (не `canonicalize`: тот даёт префикс `\\?\`), нужен Rust 1.79+. Конфиг для режима файла не читается, поэтому битый конфиг не мешает копировать путь.
- CI также выгружает `Cargo.lock` отдельным артефактом (пользователь коммитит его вручную и потом уберёт шаг, когда получит нужную версию).
- Этап 4: `winreg` только под `cfg(windows)`. Повторный `--install` перезаписывает те же ключи. Для выделения нескольких файлов Explorer запустит exe по разу на каждый, в буфере останется последний.
- Этап 4/5: запуск без аргументов = установка. Если уже установлено: вопрос «Обновить этим exe?» (пропускается, если запущена сама установленная копия), затем «Удалить?». Успех копирования молчит, окна только для ошибок и установки. Для выделения нескольких файлов Explorer запустит exe по разу на каждый, в буфере останется последний.
- Установленная копия: `%LOCALAPPDATA%\CopyTree\copytree.exe`, конфиг `copytree.toml` рядом с ней. Удаление стирает папку целиком, кроме случая, когда запущена сама установленная копия (себя exe удалить не может, папка остаётся, реестр чист). Старые установки (ключи ведут на исходный exe) считаются неустановленными, двойной клик по новому exe мигрирует их.
- Текст пункта меню: ресурс из exe на языке Windows (см. заметку про перевод ниже; раньше было `GetUserDefaultUILanguage` и текст прямо в реестре). Для папки подпись «дерево», так как копируется дерево, а не путь. Имя ключа реестра `CopyTree` не менялось (по нему удаление).
- Фоновый процесс отвергнут: достаточно записи в реестр, ноль потребления в простое.
- Игнор-список не зашит в код: дефолт вшит как текст; в `copytree.toml` рядом с exe выгружается его закомментированная копия, пользователь раскомментирует нужное.
- Если exe лежит в защищённой папке (`Program Files`), запись конфига может не пройти. Папка установки теперь фиксированная, где лежит скачанный exe, неважно.

- `show_sizes` (этап 8): по умолчанию включено (решение пользователя). Размер читается через `metadata()` только для файлов и только при включённой опции (лишний stat на файл). Для симлинка берётся размер самой ссылки, так как ссылки не разворачиваются. Размер не входит в лимит строк и не влияет на сортировку.

- Логотип: чёрный скруглённый квадрат (164x164, rx 15) и белый знак из трёх прямоугольников (вертикаль и две горизонтальные черты), геометрия снята с картинки концепта. Знак в концепте смещён от центра (поля слева 20 и справа 10, сверху 27 и снизу 38), оставлено как в концепте. `icon.ico` собран скриптом из тех же координат (PNG-кадры 16, 20, 24, 32, 40, 48, 64, 128, 256); при смене логотипа его надо пересобрать. `winresource` использует `rc.exe` из Windows SDK (есть на `windows-latest`). Explorer кэширует иконки: после обновления пункт может показать старую иконку до перезапуска Проводника. В `Cargo.lock` появятся `winresource` и его зависимости.

- Пропущенные папки (этап 8): вместо `WalkBuilder` свой рекурсивный обход через `fs::read_dir` (`Walk::visit` в `tree.rs`): иначе `ignore` не отдаёт игнорируемые записи, а пометить их нужно. Фильтры те же: игнор-список (`ignore::overrides::Override`) и `.gitignore` (`ignore::gitignore::Gitignore`, по одному на папку: `.git/info/exclude` + `.gitignore`, ближайший побеждает, `!`-правила работают). Родительские `.gitignore`, глобальный gitignore и `.ignore` по-прежнему не читаются. Пропущенная папка: строка `name/ [skipped]`, внутрь не заходим, размера нет, считается в `max_entries`. Пропущенные файлы скрыты. Побочный эффект: в каждом дереве теперь есть `.git/ [skipped]`, `.vs/ [skipped]` и т. п. Метка `[skipped]` и `... (truncated ...)` всегда на английском (это данные для буфера, не интерфейс). Недоступная папка (Access denied) показывается пустой, без ошибки.
- Перевод (этап 8): единый источник текстов `assets/strings.rc` (блоки `LANGUAGE 0x09,0x01` = en-US это запасной язык, `0x19,0x01` = ru-RU). `build.rs` дописывает файл к ресурсам exe через `winresource::append_rc_content`; в файле `#pragma code_page(65001)` для кириллицы (UTF-8). ID строк дублируются в `src/strings.rs`: **при добавлении строки править оба файла**. Подстановки `{0}`, `{1}` делает `strings::get`. `LoadStringW` сам берёт язык по языку интерфейса Windows. Текст меню: значение `MUIVerb` = `@<путь к exe>,-<ID>` (Проводник сам грузит строку из exe на языке пользователя, смена языка Windows не требует переустановки); старое значение по умолчанию при установке удаляется. Заголовок окон `CopyTree` не переводится. Тексты системных ошибок (`io::Error`) Windows локализует сама. Чтобы добавить язык: скопировать блок в `strings.rc`, поменять `LANGUAGE` и перевести. В `Cargo.toml` у `windows-sys` вместо `Win32_Globalization` теперь `Win32_Foundation`, `Win32_System_LibraryLoader`, `Win32_UI_WindowsAndMessaging`.
- Если сборка упадёт на ресурсах: сначала проверить `rc.exe` и кодировку `strings.rc` (UTF-8, `#pragma code_page(65001)`), потом существование `append_rc_content` в версии `winresource`.

- Windows 11 (решение пользователя: новое меню не делаем). Для верхнего уровня меню нужны: нативная DLL с `IExplorerCommand` (COM, `windows.comServer`), sparse package с манифестом (`windows.fileExplorerContextMenus`) и админ-права: unsigned через `Add-AppxPackage -AllowUnsigned` (Windows 11, для всех пользователей, Microsoft называет это тестовым режимом) либо подписанный пакет с сертификатом. Ломает принцип "без админа и консоли" и требует DLL-таргета, поэтому отклонено. Если вернёмся: подэтапы 9.1 DLL-заглушка + ручная регистрация, 9.2 `Invoke` запускает exe, 9.3 UAC-установка в `install.rs`, 9.4 сборка в CI.

## Приложение: дефолтный конфиг

Актуальный дефолт хранится в файле `copytree.default.toml` в корне проекта (единственный источник правды, здесь не дублируется).

Примечание к дефолтам: `build`, `out`, `dist` могут оказаться настоящими папками проекта (например, в Roblox или сайте). Если нужная папка пропадает из дерева, убрать её из списка в `copytree.toml`.
